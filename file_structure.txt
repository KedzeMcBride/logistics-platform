3. What Each Package Does
Root (logistics-platform)
The workspace orchestrator. Owns:

Turborepo pipeline (turbo.json)

Global tooling: TypeScript, Prettier, ESLint, Turbo itself

Scripts that fan out across workspaces: dev, build, lint, typecheck, test, clean, format, format:check

package.json scripts:

json
{
  "dev": "turbo run dev",
  "build": "turbo run build",
  "lint": "turbo run lint",
  "typecheck": "turbo run typecheck",
  "test": "turbo run test",
  "clean": "turbo run clean",
  "format": "prettier --write \"**/*.{ts,tsx,js,jsx,json,md,yml,yaml}\"",
  "format:check": "prettier --check \"**/*.{ts,tsx,js,jsx,json,md,yml,yaml}\""
}
packages/config — @repo/config
Purpose: single source of truth for TypeScript and ESLint configuration.

Why it exists: every app and package needs a consistent compiler target, strictness level, and lint rule set. Without a shared config, three packages drift within a week.

Exports:

@repo/config/tsconfig/base.json — generic TS settings (ES2022, strict, bundler resolution)

@repo/config/tsconfig/nestjs.json — extends base, adds decorators + CommonJS

@repo/config/tsconfig/nextjs.json — extends base, adds DOM libs + JSX

@repo/config/tsconfig/react-library.json — for future shared UI

@repo/config/eslint/base — base ESLint rules

@repo/config/eslint/nestjs — NestJS-specific overrides

@repo/config/eslint/nextjs — Next.js-specific overrides

Key rule: base configs contain only behavioral options. Path-relative options (rootDir, outDir, baseUrl, paths) belong in the consuming package's tsconfig — otherwise they resolve relative to the config package's folder, which breaks.

packages/shared — @repo/shared
Purpose: shared TypeScript code that both frontend and backend consume.

Contents:

constants.ts — APP_NAME, API_VERSION

types.ts — ApiResponse<T>, ApiSuccess<T>, ApiError, Paginated<T>

events.ts — WS_EVENTS constants and WsEvent type

Why it matters: DTOs, enums, and event names live here once, imported everywhere. When we add a mobile app later, it consumes the same contracts — no drift possible.

packages/database — @repo/database
Purpose: isolate Prisma schema, migrations, and generated client.

Current state: shell only. prisma/schema.prisma has the generator and datasource blocks but no models. Real models land on Day 4.

Planned exports:

export * from '@prisma/client' — the generated Prisma client

Helper functions (e.g., transaction wrappers) as needed

Scripts:

db:generate — generate Prisma client from schema

db:migrate — create a new migration (dev)

db:migrate:deploy — apply migrations (prod)

db:studio — open Prisma Studio

db:seed — run seed script

apps/api — @repo/api
Purpose: the NestJS backend — REST + WebSocket + BullMQ workers (later).

Current state: boots on port 3001, serves GET /api/v1 with a health payload.

Key files:

src/main.ts — bootstraps Nest, sets global prefix /api/v1, listens on PORT env or 3001

src/app.module.ts — root module (imports nothing yet)

src/app.controller.ts — defines GET / (mounted at /api/v1 due to prefix)

src/app.service.ts — service injected into controller

Extends: @repo/config/tsconfig/nestjs.json
Depends on: @repo/config, @repo/shared, @repo/database (via workspace:*)

4. Key Decisions Made (and Why)
Decision	Choice	Reason
Package manager	pnpm	Best workspace support, disk-efficient, Turborepo-native
Monorepo tool	Turborepo	Simple config, remote cache support, minimal ceremony
Node version	22.x LTS	Latest LTS, native ESM, modern fetch, supported until 2027
TypeScript	5.6+	Strict mode, noUncheckedIndexedAccess, modern decorators
Backend framework	NestJS 10	Module structure enforces service/repository separation
Config sharing	Package-name extends (@repo/config/...)	Works across the workspace; relative paths break when files move
Line endings	LF everywhere via .gitattributes	Cross-platform consistency; CI on Linux expects LF
Git config	core.autocrlf=input	Store LF in repo, LF in working tree; no surprise conversions
Nest port	3001	Avoids collision with Next.js on 3000
API prefix	/api/v1	Matches design doc; enables versioning later
apps/api/package.json name	@repo/api	Consistent scope so imports and filters work uniformly
5. Problems Hit and How We Solved Them
Problem: pnpm 12.4.2 was a broken Windows shim
Symptom: pnpm -v printed 12.4.2 and download failed
Fix: uninstalled the shim, installed via corepack prepare pnpm@9.15.0
Lesson: verify pnpm -v returns 9.x on Day 1

Problem: @repo/config wasn't resolvable from workspace packages
Symptom: Cannot find module '@repo/config/tsconfig/base.json'
Cause: pnpm doesn't hoist workspace packages to root node_modules
Fix: (1) create the package with an exports map, (2) ensure each consumer declares @repo/config in devDependencies, (3) reinstall to force symlinks
Lesson: pnpm links only where declared

Problem: rootDir in shared config resolved to wrong path
Symptom: File 'src/main.ts' is not under 'rootDir' 'packages/config/tsconfig/src'
Cause: TypeScript resolves relative paths in extends relative to the config file that declares them, not the file that extends it
Fix: removed rootDir and outDir from packages/config/tsconfig/base.json. Path options go in the consuming package's tsconfig
Lesson: base configs = behavioral only; leaf configs = paths

Problem: NestJS decorator errors (TS1241, TS1270)
Symptom: @Get() fails signature check
Cause: experimentalDecorators and emitDecoratorMetadata missing from nestjs.json
Fix: added both flags; also strictPropertyInitialization: false
Lesson: NestJS requires those two decorator flags at minimum

Problem: import * as request from 'supertest' fails to compile
Symptom: This expression is not callable
Cause: with esModuleInterop: true, namespace imports aren't callable
Fix: changed to import request from 'supertest' in apps/api/test/app.e2e-spec.ts
Lesson: Nest CLI's generated e2e test predates esModuleInterop

Problem: CRLF line endings flagged by ESLint/Prettier
Symptom: Delete ␍ on every line
Cause: Windows-generated files had CRLF, configs expected LF
Fix: created .gitattributes with * text=auto eol=lf, set core.autocrlf=input, ran git add --renormalize ., ran pnpm format
Lesson: set .gitattributes on Day 1 in any project touched by Windows

Problem: packages/database folder didn't exist when needed
Symptom: ERR_PNPM_WORKSPACE_PKG_NOT_FOUND when apps/api depended on @repo/database
Cause: Task 8's folder creation was skipped or lost
Fix: recreated the folder, package.json, tsconfig.json, and four source files (.env.example, src/index.ts, prisma/schema.prisma, prisma/seed.ts)
Lesson: verify pnpm list -r --depth -1 shows every expected workspace package

Problem: pnpm install said "Already up to date" but didn't link new deps
Symptom: workspace symlinks missing after adding a new workspace:* dependency
Cause: pnpm's fast-path skips resolution when it thinks the lockfile is current
Fix: Remove-Item pnpm-lock.yaml; pnpm install
Lesson: when in doubt, delete the lockfile and reinstall

Problem: Nest default controller returned "Hello World!"
Symptom: curl returned plain text instead of JSON
Cause: earlier file replacements for app.controller.ts and app.service.ts never landed
Fix: replaced both files with the health-check versions, hot reload picked it up
Lesson: after replacing files in a workspace, curl the endpoint — don't assume the save stuck
